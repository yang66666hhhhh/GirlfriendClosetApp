# 用户管理弹窗重设计：选中用户工作台

日期：2026-06-12

## 背景

当前用户管理弹窗已经从旧的“管理控制台”结构过渡到“当前用户工作台 + 成员管理区”，但最新体验里仍有两个明显问题：

1. 视觉主角不明确  
   顶部“当前登录用户”卡仍然占据过多注意力，导致真正需要维护的“选中用户”详情区不够突出。

2. 右侧详情区体验拥挤  
   用户在列表中选中成员后，右侧内容虽然承担了编辑职责，但空间被压缩，阅读和操作都偏紧。

用户已经明确要求：重新设计，并且以“选中的用户信息”为主。

## 目标

把用户管理弹窗重构为：

- 顶部只保留一条很薄的当前登录状态栏
- 左侧成为成员导航区
- 右侧成为真正的“选中用户工作台”

最终用户感受应该是：

- 左边选人
- 右边编辑这个人
- 当前登录用户只作为背景上下文存在

## 非目标

本轮不改以下内容：

- 本地多用户权限模型
- 登录 / 退出流程
- 用户创建、删除、重置凭证的业务规则
- 个人中心的信息架构

本轮只重排用户管理弹窗的视觉主次、布局比例和交互节奏。

## 方案选择

已确认采用：

- 方案 1：选中用户工作台

不采用：

- 双栏主从式后台表单布局
- 居中详情式展示

原因：

- 方案 1 最符合“当前选中的用户才是主角”的目标
- 保留左侧成员导航的同时，右侧可以形成完整的单用户维护台
- 对多用户场景更清晰，也比传统后台式结构更有产品感

## 结构设计

### 1. 顶部状态栏

当前顶部大卡片改为超薄状态栏。

只保留：

- 当前登录用户的小头像
- 当前登录用户名称
- 超级管理员 / 当前会话等轻状态标记

移除：

- 大头像
- 大号名称排布
- 大按钮组
- 顶部统计 chip 主展示位

作用：

- 仅提供“谁正在管理这些用户”的背景信息
- 不再承担主视觉职责

### 2. 左侧成员导航区

左侧负责：

- 标题
- 搜索框
- 新增用户入口
- 用户卡列表

设计原则：

- 这是导航区，不是详情区
- 卡片保持紧凑、清晰、可快速扫读
- 当前选中态明显，但不要过厚重

每张用户卡保留：

- 小头像
- 显示名称
- 角色 / 当前状态的短摘要
- 账号名

### 3. 右侧选中用户工作台

右侧成为整个弹窗的主内容区。

右侧结构：

1. 选中用户 Hero
2. 账号资料区
3. 安全区
4. 危险操作区

这样一来，用户会明确感觉：

- 我正在维护这个用户
- 下面这些区块都属于这个用户

## 右侧工作台细节

### 1. Hero 区

Hero 区应成为右侧第一视觉。

包含：

- 大头像
- 显示名称
- 账号名
- 角色 / 当前会话 / 凭证状态 chips

操作：

- 主按钮：保存资料
- 次按钮：更换头像
- 轻按钮：移除头像

布局原则：

- 头像和身份信息保持左主右辅关系
- 操作区不要再把内容挤碎
- 允许主按钮和次按钮换成更合理的上下或右对齐布局，而不是被迫横向并排挤压

### 2. 账号资料区

账号资料区保留双列字段：

- 账号
- 显示名称

要求：

- 让字段真正可读
- 不再被 Hero 区压到首屏以下太多
- 减少无信息量的说明文字

### 3. 安全区

安全区保留：

- 新密码
- 新 PIN
- 重置凭证按钮

要求：

- 与账号资料区形成一致的区块语言
- 保持清晰但不过度强调

### 4. 危险操作区

危险操作区保留：

- 删除用户

规则：

- 超级管理员不可删除
- 普通用户可删除
- 删除说明保持简短，不再出现大段注释

## 新增用户入口

新增用户入口继续只保留一个。

位置：

- 左侧成员导航区顶部

不重新引入顶部或右侧的重复入口。

## 布局比例

推荐新的主布局比例：

- 顶部状态栏：超薄固定高度
- 主体区：左窄右宽

主体区建议：

- 左列：成员导航
- 右列：选中用户工作台

方向上应继续把空间让给右侧，而不是继续压右侧。

## 文案原则

继续收掉多余注释。

保留：

- 区块标题
- 必要短说明

删除或压缩：

- 重复解释入口作用的话
- 已经能通过布局表达清楚的说明句
- 过长的删除或状态解释

目标：

- 让用户看结构，而不是读说明

## 交互原则

- 左侧点选用户后，右侧整块工作台切换到该用户
- 当前登录用户在列表中保留轻标识，但不霸占主视觉
- 状态栏只提供上下文，不承担编辑入口
- 用户管理仍不负责直接切换当前会话

## 测试策略

需要补充或更新布局测试，保护以下结构：

- 顶部为薄状态栏，而不是大 Hero 卡
- 左侧成员区存在唯一新增用户入口
- 右侧包含选中用户 Hero、账号资料、安全、危险操作
- 旧的“当前用户大卡”结构不再作为弹窗主布局核心

保持现有用户管理相关测试继续覆盖：

- 单一新增用户入口
- 共享头像组件复用
- 布局区块不落入 spacer row

主要改动文件：

- `ClosetApp.UI/Components/Shared/Modal/LocalUserManagementDialog.xaml.cs`
- `ClosetApp.Tests/LocalUserManagementDialogLayoutTests.cs`
- 如有必要，补充 `ClosetApp.Tests/LoginWindowLayoutTests.cs` 中对用户管理弹窗结构的断言

## 风险与约束

1. 当前代码里已经有“当前用户工作台”逻辑  
   本轮要避免继续在旧结构上叠补丁，而是直接把它降级成顶部状态栏。

2. 业务行为不能被布局改动破坏  
   例如：
   - 保存资料
   - 上传头像
   - 移除头像
   - 重置凭证
   - 删除用户

3. 不要重新引入重复入口  
   之前已经清理过一次，不能因为重排布局又长回去。

## 结论

本轮用户管理弹窗应从“当前用户工作台 + 成员管理区”继续演进为：

- 顶部：薄状态栏
- 左侧：成员导航
- 右侧：选中用户工作台

真正把视觉重心放在“正在维护的那个用户”上，而不是“当前登录的是谁”。
